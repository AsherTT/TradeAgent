## 1. 本版需要确认的结论

**Fiscal.ai 是全站唯一的主要视觉参考；Quartr 是研究阅读与证据核验的交互参考。**

产品以公司研究工作区为基础，同一份研究可以在“研究视图”和“数据视图”之间切换。
两种视图使用同一套字体、颜色、侧栏、按钮、表格、图表和状态组件，不形成两个不同风格的网站。

本版建议确定以下默认方向：

1. 桌面优先，兼顾平板和手机；中文优先，组件结构支持后续英文。
2. 浅色作为默认主题，深色采用同一套语义色和组件结构，后续一起验收。
3. 风格为安静、清晰、专业的现代金融研究工具；装饰和动画保持克制。
4. 公司与研究是一级产品对象，证据、论点、预测、策略与评估围绕它们关联。
5. 首版以已有后端可支持的研究流程为主；未具备真实资格的功能明确显示状态。
6. 为账户、工作区、用量和订阅预留一致的信息结构；本轮不假定收费功能已经可用。

确认本文件表示确认设计方向及分阶段范围，不代表完整后端、P10 全部验收或 SaaS 商业上线已经完成。

## 2. 产品定位与设计原则

TradeAgent 是可追溯的股票研究与量化分析工作台。用户通过公司资料、财务、行情、事件和原始证据建立研究论点，并观察预测和策略结果。

产品主要支持三种任务：

- 快速理解：找到公司，查看已有研究、数据情况和主要缺口。
- 深入研究：提交问题，观察执行过程，阅读分析，核验引用及时间准入。
- 持续验证：查看论点版本、冻结预测、结果成熟度，以及策略和回测记录。

设计原则：

- 让当前任务占据视觉中心；导航、设置和辅助信息保持次要层级。
- 将总结、事实、来源解释、模型判断和数据缺口分别呈现。
- 数据密度随任务调整：研究视图侧重阅读，数据视图侧重比较。
- 提供来源、时间、单位、币种、复权方式和计算口径，不让漂亮图表遮住数据限制。
- 页面可直接打开、刷新和返回；关键状态由服务端恢复。
- 所有公开交付使用 TradeAgent 自身品牌、文案及有权使用的素材。

## 3. 两个参考网站如何分工

参考的是可访问页面的具体组件和工作方式，正式产品使用下面的统一分配。

| 产品区域 / 页面 | 主要参考 | 采用的内容 | TradeAgent 自行设计的内容 |
| --- | --- | --- | --- |
| 全局应用框架 | Fiscal.ai | 金融工作区的导航层级、搜索入口、内容组织和紧凑控件 | 工作区切换、对象关联、权限和真实状态 |
| 工作台首页 | Fiscal.ai | 列表、摘要与数据面板的排布方式 | 最近研究、进行中任务、需要补齐的证据 |
| 公司概览 | Fiscal.ai | 公司标题区、分类标签、指标和图表组织 | 永久证券身份、分析截止时间、来源资格 |
| 财务与分部分析 | Fiscal.ai | 多期表格、图表、周期选择和指标层次 | 已支持字段、来源说明、不可比和缺数据状态 |
| 行情与技术指标 | Fiscal.ai | 图表周边结构、指标选择、数据说明 | 复权模式、周期、窗口不足和行情资格 |
| 公司催化剂 / 事件 | Fiscal.ai 为主，Quartr 为辅 | 时间顺序列表；点击后展开原始材料 | 事件解释、引用验证和公司相关性限制 |
| 新建研究 | 全局采用 Fiscal.ai，问题输入借鉴 Quartr | 集中的问题输入、清晰的上下文选择 | 时间模式、研究期限、预算与数据条件 |
| 研究执行详情 | TradeAgent 原创，沿用统一视觉系统 | 阶段列表、状态和预算摘要 | 持久化进度、取消、重规划、失败和缺口 |
| 研究报告 / 研究视图 | Quartr | 材料、分析正文、证据并排的阅读结构 | 部分报告、完整分析准入、财务和催化剂限制 |
| 原文与引用核验 | Quartr | 引用关联、侧栏证据、文档与分析并排 | 已保存片段、来源时间、信任和扫描状态 |
| 证据库 / 材料详情 | Quartr | 材料列表、筛选与阅读结构 | 访问权限、时间准入、片段和全文可用性 |
| 研究历史 | Fiscal.ai | 表格、筛选、排序与详情入口 | 分页查询、真实研究状态和预算字段 |
| 论点与预测 | TradeAgent 原创，沿用统一视觉系统 | 一致的详情页、版本列表和关联入口 | 不可变预测、论点生命周期、概率与成熟度 |
| 策略与回测 | Fiscal.ai 的数据呈现方式 | 参数、图表、统计和对比的视觉语法 | 策略约束、非执行交易意图、成本和质量门槛 |
| 预测评估 | Fiscal.ai 的数据呈现方式 | 对比表、趋势和统计布局 | cohort、样本成熟度、回放完整性和缺样本说明 |
| 设置、账户、用量、订阅 | TradeAgent 原创，沿用统一视觉系统 | 全站一致的设置页和表格组件 | 账户、团队、权限、订阅和额度规则 |
| 对外产品首页、价格页 | 独立的 TradeAgent 产品表达 | 与应用共享色彩、字体和控件语言 | 产品介绍、真实功能清单、价格和商业文案 |

Quartr 的布局进入产品后要换成全站统一的设计变量，不单独使用另一套绿色强调色、标题字体或按钮样式。
研究与数据视图的区别来自内容排列和操作流程，不依赖大幅换色。

## 4. 统一视觉规范

以下是本版拟定的 **TradeAgent 原创设计值**，不是已经从 Fiscal.ai 实测提取的 CSS。
复刻阶段会对照可访问的参考页面校准细节，最终产品仍采用一套统一规范。
布局和主色的实质变更需要更新本文件并重新确认；实现中的细小间距调整可以在验收时记录。

### 4.1 色彩与主题

| 语义 | 浅色提案 | 用途 |
| --- | --- | --- |
| 工作区背景 | `#F6F8FB` | 主内容背景 |
| 内容表面 | `#FFFFFF` | 侧栏、表格、阅读区、弹层 |
| 主要文字 | `#172033` | 标题、正文、数值 |
| 次要文字 | `#5F6F84` | 单位、时间、说明 |
| 结构线 | `#DDE4ED` | 表格分隔、输入边界和必要分区 |
| 主强调色 | `#315CEB` | 当前导航、主要操作、选中标签 |
| 轻强调背景 | `#EEF2FF` | 选中区和轻量交互提示 |
| 成功 / 通过 | `#16734A` | 已完成的操作、已通过的资格 |
| 警示 / 待补齐 | `#8A5B12` | 证据不足、待验证、费用未知 |
| 错误 / 拒绝 | `#B4233B` | 失败、输入错误、准入拒绝 |

状态必须同时具有文字或图形说明，不仅依赖颜色。行情涨跌方向也有正负值或箭头。
图表使用稳定的类别配色；不让每个指标卡都拥有不同的装饰色。
深色主题采用相同语义角色，单独验证对比度与图表可读性。

### 4.2 字体、排版与组件

- 默认使用系统无衬线字体和中文系统字体，不直接复制参考网站的字体文件。
- 应用正文以 14px 为基础，报告正文 15–16px，重要标题 20–28px；辅助信息通常不低于 12px。
- 数值使用等宽数字，明确单位、币种和正负号；小数位按指标口径统一。
- 间距采用 4px 基础尺度；主要内容区通常使用 24px 内边距。
- 常规控件约 36–40px 高；触屏有效点击区域至少 44px。
- 组件圆角以 8px 为主，较大表面可采用 12px；避免所有内容都装入厚重卡片。
- 阅读区限制正文行宽；财务表格可以占用更宽内容区。
- 阴影主要用于浮层、菜单和弹窗；普通表格和阅读内容依靠留白和轻分隔组织。
- 交互反馈约 120–180ms，并尊重减少动画的系统设置；不使用循环装饰动画。
- 提供明确的键盘焦点、标签、错误提示和可关闭的弹层。

### 4.3 全局应用框架

桌面左侧为可折叠导航，顶部为当前位置与搜索入口，右上角为工作区和账户操作。
主内容顶部显示当前公司 / 研究标题、时间上下文、状态和主要操作。

侧栏约 216–240px。桌面采用分栏；平板收起辅助栏；手机采用主页面加可返回的证据详情。
不把桌面三栏机械缩成手机上的三条窄列。

首页、表格、报告、策略页均复用同一侧栏和头部，避免进入不同模块时失去位置感。

以下是 **前端产品路由提案**，不是声称这些后端 API 已经存在。
`instrumentId` 使用永久证券身份；ticker 只用于显示和受控搜索。

| --- | --- | --- |
| `/app` | 工作台：最近研究、运行中任务、数据缺口 | 核心流程，需要研究列表接口 |

| `/app/companies/[instrumentId]` | 公司概览及分类标签 | 先展示真实可读数据，完整面板后续扩展 |

| `/app/research` | 研究历史、筛选和分页 | 核心流程，需要列表接口 |
| `/app/research/[researchId]` | 执行状态、预算、诊断、取消 | 核心流程 |
| `/app/research/[researchId]/report` | 研究视图和数据视图 | 核心流程 |
| `/app/evidence` | 可访问证据 / 文档列表 | 只在读取与权限契约确定后启用 |

完整 SaaS 导航是长期设计目标。当前版本只开放能使用的入口，不制造一整排点不开的菜单。

## 6. 核心页面与交互

### 6.1 工作台与公司页面

工作台优先展示最近研究和进行中任务，帮助用户继续已有工作。
公司页面将数据、研究和来源关联起来。图表缺少合格输入时展示原因，不绘制替代曲线。
多期财务、债务和分部页面随着对应后端完成逐步开放。

### 6.2 新建研究与执行详情

用户选择公司、输入问题，明确研究期限、当前研究或固定截止时间，并设置预算。
提交成功后进入返回的 research ID 对应详情页。

第一版使用现有轮询能力，并处理停止轮询、页面恢复、断线和再次进入。
进度以已持久化阶段和状态呈现；服务端未提供可靠比例时，不编造“完成 75%”。
取消后显示后端确认的状态，不宣称外部调用一定没有发生。

### 6.3 双模式报告

同一报告页面提供“研究视图 / 数据视图”：

- 研究视图：正文居中，材料和原文作为辅助区域；摘要、事实、解释、限制和缺口有明确层次。
- 数据视图：财务、技术指标、催化剂及来源表格；每个数值可以追溯到对应证据或口径。
- 两者共享研究 ID、公司身份、分析截止时间和证据集合。
- 切换视图不自动重新调用模型或抓取数据。
- 当前是异步研究任务，不承诺已经具有实时多轮聊天。首版可提供“新建后续研究”，明确建立新任务。

点击引用时，通过 `?evidence=[evidenceId]` 等可恢复的页面状态打开证据栏。
手机进入证据详情后可返回报告并保留位置。无全文或页码映射时，只展示真实保存的片段及安全来源链接。

### 6.4 论点、预测、策略与评估

论点页展示版本、依据与失效条件；冻结预测保持不可变。
部分报告不提供绕过准入的预测冻结操作。
系统置信度、模型方向概率、数据质量和成熟度分别展示。

策略页使用后端计算出的指标和统计，不在浏览器重新解释金融口径。
策略结果只表达研究、回测和非执行交易意图，不添加券商下单流程。
评估页说明样本范围和成熟度；没有真实成熟样本时不展示模拟准确率作为真实成绩。

## 7. 状态与数据诚实性

| 情况 | 用户看到的表达 | 必须保留的边界 |
| --- | --- | --- |
| pending / running | 排队中 / 研究中，阶段与预算使用 | 不编造实时完成百分比 |
| complete | 研究过程完成；完整性另行显示 | 单独读取 `complete_analysis` 等准入结果 |
| insufficient_evidence | 证据不足；可读部分报告与缺口 | 不显示完整投资结论 |
| failed / cancelled | 已失败 / 已取消；安全诊断与可用入口 | 不泄露敏感供应商错误原文 |
| 预算限制 | 根据后端诊断显示限制项 | 当前预算耗尽不是单独的 ResearchStatus 枚举 |
| null 指标 / 窗口不足 | “—”和具体原因 | 不转成 0、不画成零值数据点 |
| UNVERIFIED 数据 | “来源资格待验证”和影响范围 | 不标为已认证实时数据 |
| 模型 token / 费用未知 | “未知”或“供应商未返回” | 聚合占位 0 不当作无消费 |
| 当前研究截止时间待建立 | “分析截止时间待建立” | 不以浏览器当前时间代替 |
| 无成熟预测样本 | “暂无真实成熟样本” | 不以 fixture 或回填结果代替 |

渲染外部文本时保持其不可信属性，不直接执行来源 HTML 或外部脚本。
安全来源链接与私有材料读取遵守服务端的准入、权限和时间规则。

## 8. ai-website-cloner-template 的使用计划

### 8.1 隔离与固定来源

在 `D:/桌面/Trade` 下准备独立的复刻实验项目，正式仓库只接收审查过的组件和设计变量。
开始前固定并审查一个明确的模板 commit，记录来源、版本和许可证；不运行浮动分支上未经检查的脚本。
本设计阶段未克隆模板、未安装前端依赖、未执行复刻脚本。

### 8.2 参考范围与可访问性

已指定的参考网址：

- Fiscal.ai：<https://fiscal.ai/>。
- Quartr Pro：<https://quartr.com/products/quartr-pro>。
- Quartr 官方交互说明：<https://quartr.com/features/ai-chat>。
- 模板：<https://github.com/JCodesMore/ai-website-cloner-template>。

公开展示页与登录后的产品工作台必须区分。开始复刻前记录精确 URL、页面、状态与可访问范围。
当前依据公开产品说明与布局提案制定方案，尚未完成登录工作台的逐页视觉采样。

可访问的实际页面采用浏览器检查和复刻流程；无法查看的内部页面，以本文件中的 TradeAgent 结构设计实现并标为原创适配。
官网截图只作为图像参考，不冒充可检查的交互页面。没有来源页面和视觉对比，不宣称逐像素复刻通过。
如果实际工作台不可访问，先完成来源清单和可独立实现的设计工作，再确认受影响的复刻范围；不把展示页复刻冒充工作台复刻。

### 8.3 复刻与适配顺序

1. 检查桌面、平板、手机，记录字体、颜色、间距、控件及加载、空、错误状态。
2. Fiscal 与 Quartr 的采样和实验产物分开保存，避免全局样式相互覆盖。
3. 对可检查的参考页面完成原样复刻，保存组件规格与视觉对照；检查类型、规范和生产构建。
4. 建立本文件的统一 TradeAgent 设计系统，以 Fiscal 为主要基调。
5. 将 Quartr 的阅读布局与引用交互放入统一设计系统，替换其原有视觉变量。
6. 替换第三方品牌、文案和不具备使用权的素材；使用自身内容与实际状态。
7. 接入自己的路由、类型化 API 客户端和后端契约。
8. 审查、修复和复验后，将可交付组件移入 `apps/web`，遵守仓库 pnpm 工作区约定。

模板提供前端基础及复刻工作方式，不提供参考产品的后端、用户账户、数据许可、预测资格或订阅能力。
之前的完成比例为排期粗估，不能作为完成率验收或商业承诺。

## 9. 与现有后端的连接

本版按当前代码和检查点区分已有能力与缺口：

| 能力 | 当前入口 / 状态 | 设计安排 |
| --- | --- | --- |
| 提交研究 | `POST /research` | 新建研究页接入；真实调用遵守来源开关与预算 |
| 研究状态 | `GET /research/{id}` | 执行详情与轮询 |
| 取消研究 | `POST /research/{id}/cancel` | 显示真实确认结果 |
| 报告 | `GET /research/{id}/report` | 双模式展示，保留部分报告与缺口 |
| 保存论点 / 冻结预测 | `POST /research/{id}/theses`，受控且需合法完整综合 | 准入与权限确定后提供操作 |
| RAG 导入 / 搜索 | 已有受控接口 | 不等同于完整文档浏览、全文定位或语义资格 |
| 评估 | `GET /evaluation/forecasts`，指定配置 cohort | 展示真实成熟度与配置边界 |
| 公司搜索、研究历史列表 | 尚需产品查询接口 | 核心首版优先补齐 |
| 论点、预测、证据及文档查询 | 尚需完整产品查询契约 | 按关联页面逐步补齐 |

前端与 API 的同源代理 / 服务端适配层需要明确配置，不假定当前 FastAPI 已经允许任意浏览器跨域访问。
供应商凭据和服务端写令牌不能放进可下载的前端包。

## 10. 长期订阅 SaaS 的设计边界

### 10.1 产品结构

工作区与账户入口从统一应用框架中预留。未来个人版可以默认只有一个工作区，团队版沿用同一结构。
公司身份可以属于共享证券目录；用户研究、材料、论点、预测和策略的访问范围必须由服务端工作区权限控制。
当前单机 / 内部研究模式不等同于多租户 SaaS，不能仅靠增加工作区下拉框宣称数据隔离完成。

### 10.2 订阅与额度

未来套餐可以围绕研究资源、可访问功能、团队协作与服务等级设计；套餐名、价格和具体额度暂不冻结。

- 订阅权益、账户额度和单次研究预算是三个不同层级。
- 前端负责解释和展示，额度扣减、权限判断及任务准入由服务端执行。
- 区分额度不足、功能未开放、数据不足和来源未获资格，不用同一种“升级套餐”提示覆盖它们。
- 付费不会改变证据与金融完整性门槛，也不会自动赋予第三方数据商业使用权。
- 未知模型成本不是零成本，不能直接用于价格承诺或毛利计算。
- 用量、支付状态、失败、退款与取消订阅需要账本和服务端幂等规则；不是一个价格页即可完成。
- 功能比较表必须对应真正可交付的能力，不把长期规划列成当前套餐已提供功能。

### 10.3 商业化前的独立验收

账户与登录、工作区数据隔离、成员权限、服务端额度控制、账单与支付事件、可观测性、数据许可、隐私和数据生命周期分别验收。
支付服务商、部署方式和套餐定价在对应阶段选择；本文件不提前绑定具体供应商。
订阅界面可以共享产品设计系统，但本轮不开放实际购买或收款。

## 11. 确认后建议的实施阶段

| 阶段 | 交付范围 | 完成条件 |
| --- | --- | --- |
| D0：设计确认 | 本文件、页面分工、默认主题、导航与阶段范围 | 用户明确确认；此时尚不写代码 |
| D1：参考采样与独立复刻 | 固定模板来源、可访问页面、组件规格和对照证据 | 区分原样复刻、仅图像参考和原创适配，限定范围验收 |
| D2：统一视觉基础 | 全局框架、表格、输入、状态、双模式布局及移动端 | 一套设计系统；演示内容明确标记；类型与构建通过 |
| D3：真实研究闭环 | 公司选择、历史、新建研究、进度、取消、部分报告、证据 | 真实接口联调；状态、刷新、直接链接和故障路径验收 |

P11 部署和真实收费开放不包含在本版设计确认中。

## 12. 设计与产品验收清单

- 全站只有一套导航、字体、色彩、控件和状态语义；Quartr 阅读区域与其他页面自然衔接。
- 公司、研究、报告和证据之间有明确且可恢复的关联路径。
- 桌面阅读与数据比较清晰；手机主要任务和证据核验可以完成。
- 有加载、空、缺口、失败、取消、权限和预算限制的实际展示。
- null、未知费用、数据资格与成熟度保持可见。
- 已有接口、拟新增接口、演示功能和未来 SaaS 功能清楚区分。
- 关键操作与信息可通过键盘访问；文字、数值与图表有足够对比度。
- 没有来源检查与视觉对照的页面，不声明原样复刻通过。
- 没有后端权限隔离和权益验证，不声明可以面向付费多租户上线。
