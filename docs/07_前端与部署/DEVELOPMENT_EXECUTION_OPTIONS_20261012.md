# TradeAgent 三个待选开发执行方案

日期：2026-10-12，Asia/Shanghai。状态：供用户选择的提案，未替代DEVELOPMENT_PLAN.md，未把待开发任务标为完成。

这次选择的是功能范围、接口补齐方式与交付顺序，不是重新选择视觉风格。三个方案都沿用已确定的Fiscal主工作台、Simply公司来源区域、Quartr报告阅读分工，保留已认可首页。整个/app包含门户、公司、研究列表/提交/状态/报告及账户入口，均逐页交付。

## 当前起点

- P10/R1未完成，R2未启动。搜索来源lab已有父弹窗、30条主参考结果、九公司331上市地点；Simply lab已有报告分栏、身份/目录及来源区域。均不是完整实时公司服务。
- 已有自有接口：账户、公司目录/详情、关注、门户、本人研究记录/变化、研究提交/状态/取消/预算/部分报告。
- 尚缺：完整公司财务序列、产品行情查询、股本/发行人映射、估值与同行、授权原文阅读及完整研究能力。分析师共识、完整新闻流和持股服务没有因来源界面出现而自动纳入首版。
- 当前服务沿用Next同源BFF → FastAPI → 领域服务/数据库。模型/worker/beat继续关闭；真实研究执行、商业来源与部署按独立准入，不因选择方案自动开启。

## 方案1：现有能力先成站

目标：先交付完整的现有产品网站，让“选公司 → 发起研究 → 看状态 → 读已有报告”在统一研究空间中可操作。

实施顺序：

1. 收尾已选搜索弹窗和Simply来源区域：补短窗口滚动、清空/关闭/焦点等已选控件状态；受限完整分析师与整公司商业报告不成为本版本前置。
2. 重构/app应用壳和门户：公司搜索、关注、最近研究、活动任务、分页与研究变化接现有接口。
3. 重构/app/companies/[instrumentId]：公司身份、关注、已有本人研究及发起研究；采用Fiscal布局，按自有对象绑定。上市地点样本留在来源对照页，未经身份映射不伪装产品证券目录。
4. 重构研究列表/提交/状态：已有条件选择、预算、取消、失败/会话处理。
5. 重构报告与账户入口：已有报告章节、引用元数据、来源/时间；原文未保存时不显示伪造全文。
6. 完成首版中英/三尺寸、导航/刷新/返回、空/错误/重试和权限验收。

后端：仅补上述交付所需的安全展示DTO或确实缺失的映射，不新建行情、共识、持股服务。公司来源区显示TradeAgent实际可查的证据/来源/更新时间，未知项明确不可用，不能照搬S&P供数说明为自有能力。

本版不显示样本价格曲线作为真实行情，也不许诺15分钟延迟。R2～R5保留为后续，先交付现有网站。现有任务接口可验证不等于已开启模型生成新报告。

验收：搜索本地目录中的真实证券，进入其稳定公司地址；关注、研究入口、任务/报告导航均到本人对象，刷新/返回正确。已有报告可读，无报告可解释；未增加业务的数据页不能计为完成。

选择后第一块交付：搜索/公司来源已选区块收尾及验收，再交付/app应用壳与门户。

## 方案2：按功能区同步交付（推荐）

目标：保留全部已确认前端路线，每次只完成一个有实际数据支撑的功能区。先完成R1现有网站，再把R2等阶段拆成小交付；不等待完整Fiscal/Simply产品都复刻完。

交付顺序与出口：

| 顺序 | 前端交付 | 后端交付 | 用户怎样验收 |
| --- | --- | --- | --- |
| 1 | 搜索与Simply已选来源区块收尾；/app应用壳、门户、公司概览 | 复用目录/关注/门户/公司/本人研究接口；必要安全映射 | 搜索真实目录证券，进入公司，关注后返回门户状态一致 |
| 2 | 研究列表、提交、状态、预算/取消、基础报告和账户入口 | 复用已有研究接口，补实际展示缺项 | 已有任务和报告可查看；无任务/失效会话/失败有正确状态，完成R1 |
| 3 | 公司报价与历史价格图；先已验证的日线窗口和周期切换 | BE-13及DATA-01/02；需要的身份映射按BE-12补齐 | 显示来源、时间、币种/调整口径；切周期真的换数据，未知或未合格不画假曲线 |
| 4 | 财务先收入/利润年度序列，再扩资产负债/现金流表 | BE-02/03：期间、修订、单位、可用时间与确定性计算 | 单元格可追溯到事实/来源；不同年度确实不同；缺项不填0 |
| 5 | 股本/市值、基础估值，随后有界同行比较 | BE-12/14/15，在有效价格和财务基础上计算 | 股数和价格时点/口径一致，公式与缺项可查；不展示来源网站评分为自有评分 |
| 6 | 报告引用到已保存原文片段、并排核验 | R3/BE-04账户授权与位置查询 | 点击引用定位正确片段；未保存全文明确范围 |
| 7 | 完整研究、Critic、论点/反证与变化界面 | R4类型化能力、预算/准入、论点回流 | 完整性与来源可核验；真实执行按独立准入，不以fixture冒充 |
| 8 | 有资格的工具/评估与整体网站验收 | R5数据/结果资格及R6端到端 | 未到期结果、未知成本或未合格历史有准确状态 |

前两块共同完成整个现有/app重构；顺序3～5按R2逐块交付，后续沿用R3～R6。季度/TTM和更多财务概念也是后续小块，不要求年度首块一次覆盖全部三表。每块先列来源布局和实际数据需求，再做spec、复刻、必要后端、接线与手验。

暂不纳入：分析师共识/目标价全库、完整新闻平台、股东/内部人交易产品、实时分时行情、完整Fiscal与Simply的所有商业章节。登记候选需求，不删除未来方向，也不增加为R1必过门槛。

选择后第一块交付：明确搜索/公司来源本轮状态边界并收尾，然后把对应能力接入/app门户与公司概览。无需先补财务/行情后端才能开始这块。

## 方案3：完整公司终端

目标：把图中的Fiscal公司页及Simply完整公司分析章节作为长期产品范围，除原有研究链外，增加明确的数据模块；每个页签分别开发，不一次开工全部模块。

实施顺序：

1. 冻结首版公司终端页签/章节映射、来源可访问范围、已有/新增接口和数据供应商方案；商业API可用范围、价格与展示许可尚待确认，不自动购买。
2. 先完成现有网站与公司终端外框，接公司/关注/研究/账户；来源对照页可展示采集样本，但不计数据功能完成。
3. 补行情与历史图、多期财务及分部/KPI、股本/估值/同行，并按不同期间与数据用途验收。
4. 补公司材料/申报文件目录与阅读；完整IR音视频是否纳入另定范围，不能随页签自动承诺。
5. 单独建设Estimates分析师共识、News新闻/事件、Ownership股东与内部人交易的采集、持久化、查询及质量/时点契约。AI预测不是分析师共识，股本不是持股分布。
6. 为Simply拟保留的估值、增长、财务健康、分红、管理/持股章节逐项提供真实输入和自有计算；不直接复制原站结论、评分或供应商身份。
7. 完成研究/证据/论点与工具接入，各已承诺页签逐项验收，再做整体验收。

后端：除了R2～R5既有任务，还须新增共识、新闻、持股等正式任务，先更新契约、架构和数据依赖。继续复用原后端，不另起技术栈。

来源权限影响：受限章节可能缺完整DOM/交互样本，因此其全状态1:1验收可能延后；数据源不成立时不能把该页签记完成。其他已具备样本和接口的页面可以继续交付。不是购买网页会员就自动获得应用的数据API授权。

验收：首版承诺的每个页签有真实数据、来源/时间/缺项状态和可操作接口；交付期间以模块已完成清单说明，不承诺一轮完成完整终端。实时交易、券商同步、社交、收费系统和全市场筛选仍在本方案之外。

选择后第一块交付：先交付终端功能/接口/数据来源映射与新增任务清单，明确新增工作，再实施现有产品外框与接线。数据模块总体工作量最高。

## 所有方案的执行规则

- 继续按apps/web中的clone-website技能，以真实DOM/CSS/素材/状态为依据；对选定区块保持精确复刻，不以通用卡片替代。英文来源对照，中文为适配，语言切换保留上下文。
- “区块视觉完成”“接线完成”“真实数据/模型资格”分别记录。样本只用于来源验证，不制造研究结果、价格、共识或身份映射。
- 每个已定义的大R阶段code-review一次；R1现有流程继续沿用原代理，仅新增差异定向复核，不把每个页面都变成新整阶段审查。
- 提交说明中文；正常push沿用既有授权。商业服务购买、真实执行和部署不包含在方案选择里。
- 选定后只更新现有DEVELOPMENT_PLAN.md的范围/顺序与相关架构，不建立第二份任务状态表。未选定前，本文件仅是提案。

推荐方案2：保留最终前端范围与原架构，先使现有网站可用，再按页面功能区补接口；工作量增长有明确出口，符合“所有前端一步一步做”的要求。
