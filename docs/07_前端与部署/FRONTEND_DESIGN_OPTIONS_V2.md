## 1. 推荐结论与本轮变化

推荐 **V2-B：可视化研究门户**。

由 Simply Wall St 主导整体产品体验和视觉组织，Fiscal.ai 提供财务分析的深度，Quartr 提供研究阅读与证据核验的交互方式。正式应用使用同一套 TradeAgent 品牌、导航、字体、颜色和组件。

上一轮是“以专业公司研究工作区为中心，再增加阅读视图”。本轮推荐改为“以用户的研究门户为入口，先理解概览，再进入公司和证据”。公司的深度数据页仍然保留，不把专业分析简化成只有卡片的产品。

三个候选名称均带 V2 前缀，避免与上一轮 A/B/C 混淆：

| 对比 | V2-A：可视化增强终端 | V2-B：可视化研究门户（推荐） | V2-C：个人门户 + 专业工作区 |
| --- | --- | --- | --- |
| 一级产品对象 | 公司与研究任务 | 关注公司、研究集合与持续跟踪 | 个人研究资产与专业研究项目 |
| 全站主要参考 | Fiscal.ai | Simply Wall St | Simply Wall St 的外层门户，内部使用统一 TradeAgent 系统 |
| 默认体验 | 密度较高的金融工作台 | 清晰的概览、图表与分层阅读 | 简洁门户进入高密度专业视图 |
| Simply Wall St 的位置 | 增强层 | 产品主导层 | 获客和日常使用的入口层 |
| 相对设计与实现复杂度 | 较低 | 中等 | 较高 |
| 最适合的定位 | 专业研究工具 | 面向个人与进阶用户的订阅 SaaS | 面向个人、专业用户和团队的长期平台 |

复杂度为规划判断，不是已经测量的工时。三者都需要补齐产品查询接口与 SaaS 能力；前端风格不会降低真实持仓等领域功能的开发成本。

## 3. Simply Wall St 值得融合的六部分

下面是 TradeAgent 的改造建议，而非对参考站功能的完整转述。

| 融合方向 | TradeAgent 的具体表达 | 首版与后续边界 |
| --- | --- | --- |
| 产品演示 | 首页使用标签切换的产品窗口，演示概览、公司、证据、论点四个场景 | 使用自己的界面和素材，展示可用能力或明确标注的设计预览 |
| Portal 概览 | 关注公司、最近研究、执行中任务、待核验证据、最近变化 | 需要关注列表与研究历史等产品接口；不使用资产净值伪装研究门户 |
| 可视化公司摘要 | 财务趋势、主要发现、风险与缺口、最近事件；从摘要进入详细分析 | 财务事实与模型解释分别呈现；图表依赖合格数据 |
| 多维概览 | 用独立维度卡片和趋势图展示公司情况 | 不直接套用 Snowflake 名称、图形和评分体系；没有合格规则时不生成综合分数 |
| 发现与跟踪 | 用户整理主题研究集合，查看来源明确的公司事件 | 自动股票筛选、全市场扫描与通知另需数据、查询和任务系统 |
| 论点持续跟踪 | 研究结论关联论点、版本和冻结预测，显示支持与反证 | 不把已有保存接口等同于完整论点查询、协作或社区系统 |

首版的多维摘要可以列出“财务、估值、事件、证据情况”等独立模块，但不会把证据完整程度当成公司投资质量分数。估值或预测未具备时，明确说明缺什么，并允许进入来源核验。

## 4. V2-A：可视化增强终端

### 整体基调

维持 V1 的 Fiscal 主导方向：浅灰底、白色内容区、蓝色强调、紧凑导航和数据表格。Simply Wall St 增加易读摘要和演示层，Quartr 负责深度阅读。

设计提案沿用 V1 主色 `#315CEB`，背景 `#F6F8FB`；间距偏紧凑，常用卡片圆角 8–12px。报告区保持舒展，表格区提高密度。

### 页面分工与路径

- 官网首页：Simply Wall St 的产品演示结构，换为 TradeAgent 蓝色品牌语言。
- 登录后首页：Fiscal 式工作台；上方放最近任务摘要，下方以研究列表为主。
- 公司概览：Fiscal 公司框架，上半屏加入 Simply Wall St 式视觉摘要。
- 财务、行情、策略和评估：Fiscal 数据呈现方式。
- 报告、证据库和原文：Quartr 的并排阅读方式，使用全站蓝色与统一控件。
- 论点、任务执行、设置和订阅：TradeAgent 自行设计。

主要路径：**搜索公司 → 公司概览 → 财务或发起研究 → 报告 → 引用原文 → 保存论点**。

### SaaS 适配与取舍

专业工具定位清楚，与当前研究后端最接近。未来订阅围绕研究额度、数据历史、导出和团队能力演进。代价是 Simply Wall St 对全站体验的改变较小，门户和日常跟踪感弱于另外两案。

## 5. V2-B：可视化研究门户（推荐）

### 整体基调

Simply Wall St 主导页面层次：先展示用户关心的公司和研究变化，再展示专业细节。统一采用深墨色导航、浅色画布、蓝绿强调和清晰图表；官网可用深色舞台突出产品窗口，应用默认浅色利于长时间阅读。

原创配色提案：导航 `#14232B`、背景 `#F5F8F7`、内容表面 `#FFFFFF`、正文 `#172B34`、主强调 `#137C80`。通过与风险等语义状态仍分别使用明确标签和独立颜色。卡片圆角 12px，内容间距 24–32px；不靠大量阴影装饰层级。

### 导航与页面分工

一级导航：**概览 / 关注公司 / 研究 / 证据 / 论点与预测**。策略与评估放在“分析工具”分组；后续具备真实能力再增加“组合”。账户、工作区、用量和订阅位于固定账户区域。

| 页面 | 主要参考 | 拟定内容 |
| --- | --- | --- |
| 官网首页 | Simply Wall St | 主张、四场景产品演示、研究流程、真实功能范围、订阅入口 |
| 登录后 Portal | Simply Wall St | 关注公司、最近研究、待处理事项、来源明确的变化；不用虚构收益填充 |
| 关注公司 / 研究集合 | Simply Wall St | 公司卡片、分组、标签、近期研究；不先承诺全市场智能筛选 |
| 公司概览 | Simply Wall St | 公司摘要、合格趋势图、主要发现、风险与缺口、最近事件 |
| 公司财务 / 行情 | Fiscal.ai | 多期表格、指标图、周期选择、来源和口径说明 |
| 研究报告 | Quartr | 摘要、章节正文、引用列表、证据侧栏 |
| 证据库 / 原文 | Quartr | 材料列表、已保存片段、时间与资格、返回引用位置 |
| 论点与预测 | Simply Wall St 的叙事思路 + 原创 | 支持证据、反证、版本、预测条件和成熟度 |
| 策略 / 回测 / 评估 | Fiscal 的数据布局 + 原创 | 参数、结果、样本和质量状态；待稳定接口 |
| 新建研究 / 执行 / 用量 / 订阅 | 原创 | 问题、公司身份、时间模式、预算、任务状态和账户权限 |

Fiscal 和 Quartr 的组件迁入后全部换成这套字体、导航、颜色和按钮。页面之间的区别来自阅读与数据密度，不出现三种独立品牌。

### 用户路径

**Portal → 关注公司 → 公司概览 → 查看财务或发起研究 → 阅读报告 → 点击引用核验 → 保存和跟踪论点 → 返回 Portal 查看变化。**

Portal 卡片进入真实对象详情，研究完成进入报告，引用进入已保存片段或可访问原文。无全文时明确显示片段范围；缺少接口的设计入口标注后续能力，不使用看似成功的假跳转。

### SaaS 适配与取舍

日常回来查看研究变化和维护关注公司，是持续使用的产品理由；深度分析为进阶用户提供扩展空间。未来可以探索 Free / Pro / Team 的层级，但本轮不确定价格、额度和上线日期。

相比 V2-A，需要补充研究历史、关注列表和聚合查询；相比 V2-C，不需要首版维护两套使用模式。推荐它，是因为它回应了用户对 Simply Wall St 门户审美的偏好，同时保留 TradeAgent 的研究、证据与量化特点。

## 6. V2-C：个人门户 + 专业工作区

### 整体基调

官网和登录后首页由 Simply Wall St 的视觉组织主导；用户进入项目后，切换到 Fiscal 式高密度分析工作区；报告与原文采用 Quartr 的阅读结构。

统一使用墨色、青蓝色和白色。门户使用 24–32px 的空间与较大的图表，专业视图使用 16–24px 的空间与紧凑表格。两者共享品牌、字号体系、控件与状态；区别是内容密度与导航上下文。

### 页面分工与路径

- 官网、个人 Portal、公司视觉概览：Simply Wall St。
- 研究项目、财务、公司对比、策略与评估：Fiscal。
- 报告、原文、跨材料核验：Quartr。
- 项目关联、模式切换、权限、预算和订阅：TradeAgent 原创。

主要路径：**个人 Portal → 选择公司或研究项目 → 打开专业视图 → 财务 / 研究 / 策略 → 证据核验 → 返回 Portal**。

切换时保留公司、研究任务和已选材料。使用同一条对象路由下的视图切换，不建设两套公司数据库或重复任务系统。手机优先提供 Portal、报告与任务状态，高密度分析按内容折叠。

### SaaS 适配与取舍

适合未来同时服务个人用户与团队研究项目。但需要更多项目管理、状态恢复、权限设计和两种密度的验收，首版更容易扩大范围。

专业视图是否付费属于之后的套餐决策；证据、数据资格与风险说明在所有可用套餐中都要完整呈现。当前不建议为了未来收费而提前建设大量团队和组合功能。

## 7. 首页轮播产品演示如何融合

三案都保留产品演示区，但演示内容体现各自定位。推荐 V2-B 使用四个场景：

1. **研究门户**：关注公司、最近研究、需要处理的事项。
2. **公司分析**：摘要、财务趋势，切换至多期数据。
3. **证据核验**：报告中的引用打开右侧原文片段。
4. **论点跟踪**：查看支持证据、反证和论点版本。

形式：一组场景标签对应一个大的产品窗口，支持手动切换和暂停。完成真实界面后录制自己的短视频；早期用明确标注“设计预览”的静态分镜，不把未完成能力包装成已上线。

建议每段约 10–15 秒，作为拟定录制长度；不声称是原站播放时长。静音展示，提供海报帧，当前场景按需加载，手机简化为图片和手动切换。尊重减少动画设置，所有标签可用键盘操作。

展示“研究变化”而不是承诺收益。原站视频用于理解镜头、节奏和信息层级；正式产品使用 TradeAgent 自己的界面录屏、文案和可使用的素材。

## 8. 如何合理使用 ai-website-cloner-template

模板的主要价值是把已观察到的页面重建为可维护的前端。可公开观察的视觉、布局和交互可以进入复刻范围；视频画面只能证明展示内容，不能证明背后的真实操作、路由和服务器规则。[模板说明](https://github.com/JCodesMore/ai-website-cloner-template#how-it-works)

### 8.1 确认后的顺序

1. **冻结一个方案与页面清单。** 明确哪一个来源主导全站，哪些来源只贡献组件；先定 1440 / 1024 / 390px 等验收视口。
2. **固定模板版本并建立独立 clone lab。** 按前端策略在 TradeAgent 仓库外建立实验项目，先审查固定版本；本轮不创建。
3. **分别采样来源。** 截图、字体、计算样式、布局、切换、滚动、加载和错误状态；保存页面与组件规格。受限页面标记未采样，不猜成已复刻。
4. **先做来源的纯复现。** 每个来源独立保留规范和视觉对比，验证观察到的结构；不直接把三套全局样式叠加在一起。
5. **再做统一改造。** 主来源确定 TradeAgent 视觉变量，辅来源提供布局与交互；统一按钮、表格、侧栏和状态，换成自身品牌与文案。
6. **接入自身对象和路由。** 公司身份使用永久 instrument UUID；研究、证据和论点各有稳定地址，刷新、返回和权限失败可恢复。
7. **联调真实后端，再制作录屏。** 验证提交、运行、取消、报告、引用和保存流程；独立验收视觉、可访问性、性能与功能。

### 8.2 推荐 V2-B 的采样包

| 来源包 | 精确入口 | 核心采样目标 |
| --- | --- | --- |
| Simply Wall St 官网 | `https://simplywall.st/` | 导航、首屏、产品展示切换、滚动层级、响应式 |
| Simply Wall St Portal | `https://simplywall.st/portfolio/demo` | 概览、标签、列表、分析布局；仅已观察的状态 |
| Simply Wall St 公司 | `https://simplywall.st/stocks/us/tech/nasdaq-aapl/apple` | 摘要到章节的层级、图表容器、事件入口 |
| Fiscal 数据 | `https://fiscal.ai/` 和之后可合法访问的确切应用页面 | 多期财务、数据控件、图表；官网示意图只作示意依据 |
| Quartr 阅读 | `https://quartr.com/products/quartr-pro` 和之后可合法访问的确切产品页面 | 材料、报告与引用阅读；受限交互另写原创规格 |

不用一次性整站复刻三家。先完成主来源的代表页面，再补足少量财务与阅读组件，是更容易维持统一风格和控制返工的方式。

### 8.3 模板能完成与需要自行完成的部分

- 模板可协助：已观察布局、字体和间距、响应式、展示动画、可观察控件状态，以及隔离的演示数据结构。
- 仍要自行完成：数据契约、对象关联、真实跳转、持久化、查询聚合、来源资格、任务恢复、账户和权限、计费与配额。
- 单独建设：证券搜索与覆盖、自选、事件更新、完整财务与估值、真实组合和收益、通知、团队协作。

不能用视觉完成比例推导 SaaS 完成比例。本轮没有跑实际复刻，因此不承诺“模板自动完成多少百分比”或具体工期。确认后用主来源的一页完整采样与验证来校准投入。

## 9. 功能边界和阶段范围

### 9.1 可以围绕现有契约开展的研究闭环

研究提交、任务状态、取消、报告读取、符合条件的论点保存、已配置 cohort 的预测评估入口已有后端基础。具体入场资格以检查点和契约为准。

任务完成不等于分析完整。正式界面同时说明报告完整性、数据资格、缺口和来源时间；费用未知时不显示为零；空值不补成财务零值。

### 9.2 门户需要的产品扩展

研究历史与聚合列表、证券搜索、自选和研究集合、证据和论点的完整查询、公司事件聚合、完整财务数据等需要新增或补齐接口。门户布局可以先确认，但这些内容不能凭现有单任务接口当作已可用。

### 9.3 真实 Portfolio 单独排期

“研究门户”组织公司和研究，“投资组合”核算用户真实持仓。若后续建设真实组合，需要交易流水、成本、公司行动、行情、分红、汇率和收益口径，以及相应持久化与质量校验。

券商同步、收益归因和组合估值不是复刻一个 Portal 页面就会获得的功能。建议顺序为：研究门户 → 手动或导入组合 → 核算与验证 → 再评估券商同步。

### 9.4 SaaS 产品化

所有方案均预留账户与工作区、用量和订阅位置。真正收费前补齐身份认证、租户隔离、服务端权限与额度、支付状态和幂等回调、取消与续订体验、运营与支持能力。

账户订阅额度与单次研究预算分别管理。首版不承诺精确实时模型成本，不以套餐放宽数据或证据质量门槛。

## 10. 选择建议与确认后的交付

- 选择 **V2-A**：希望尽快形成专业研究终端，并保留上一轮 C 的主要基调。
- 选择 **V2-B**：希望 Simply Wall St 的视觉组织真正进入全站，并以个人和进阶用户的订阅 SaaS 为主要方向。
- 选择 **V2-C**：愿意投入更多产品和权限设计，为个人门户、专业项目和团队场景建立两种密度的体验。

当前推荐 V2-B。它把门户、公司理解、财务深度和证据核验串成一个完整路径，未来仍可扩展专业工作区与真实组合，不需要首版承诺这些功能已经完成。

用户已选择 V2-B，并要求通过模板项目尽量一比一复刻。已收敛为 [单一方案设计基线](FRONTEND_DESIGN_V2_B_BASELINE.md)，执行时先完成原站纯复现，再进行统一产品适配与后端联调。
