## Browser observations and incomplete interactions

The old saved-permission refusal was not returned in this run. Screenshots and
read-only DOM/computed styles succeeded, after refreshing the existing tab.
Some operations still timed out. Neither permission recovery nor a root cause
for all tool timeouts is established by these observations.

Read-only expression strings succeeded for bounded extraction; an earlier
function-form call timed out. This is an observed difference, not a proven
serialization/runtime defect. `document.fonts` iteration is unsupported in the
read-only scope and is not used as font-loaded verification.

The asset-bundle font batch failed with `TypeError: Failed to fetch` for marketing
and Google font URLs. Its failures are retained in `bundle-fonts-20261006.json`.
This was not a saved-permission rejection. A retained inventory became invalid
after page-state changes; regenerate it before further bundles.

`downloadMedia` succeeded for the three media files. After video download, the
read-only document URL was the MP4 URL; later tab metadata still showed the
homepage. A Back operation eventually left the outer tab at `about:blank`.
Normal homepage navigation/reload restored readable source content. Therefore
verify both the tab address and fresh DOM after every download; do not assume
Back restores the correct source document. Per-tab concurrent download attempts
were rejected as already in progress; use sequential downloads.

`desktop-features-click-20261006.txt` records the result of clicking Features.
The measured state in
`desktop-features-state-20261006.json` is `aria-expanded=false`, dropdown
`display:none`. The interaction model is still unresolved, so it cannot be
specified as a click-to-open implementation from this probe.

Only an early PageDown transition was observed (scroll position ~874px). A full
scroll sweep, hover sweep, all research-tab states, menu states, breakpoint
transitions and time alignment remain incomplete. No page builder was dispatched.

serif element weight, and the scaffold theme still referencing upstream Geist

face). The template theme now uses its generated local sans/mono variables.
Lint, strict typecheck and production build passed again after these corrections.
The capture count was also corrected to 557 retained nodes at each width.
Both independent reviewers rechecked and closed their findings. Fresh browser
computed styles after restarting the stale preview confirmed the scaffold uses
the generated local `geistSans`/`geistMono` families. Details and the separate
Standards/Spec reports are in `REVIEW_20261006.md`.
